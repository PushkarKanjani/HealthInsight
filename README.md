## Architecture

```
Synthea CSVs → Apache Spark → Apache Iceberg → Trino → Apache Superset
                                    ↓
                                MongoDB
```

| Component | Role |
|---|---|
| Apache Spark | Distributed ETL — reads CSVs, transforms data, writes Iceberg + MongoDB |
| Apache Iceberg | Lakehouse table format — Parquet-backed managed tables |
| Trino | Distributed SQL engine — queries Iceberg tables |
| MongoDB | NoSQL analytics store — holds pre-aggregated summary documents |
| Apache Superset | Web dashboard UI (connected to Trino) |

## Setup

### 1. Copy environment file
```bash
cp .env.example .env
# Edit .env with your absolute paths
```

### 2. Verify all services are running
```bash
bash scripts/verify_services.sh
```

### 3. Place Synthea CSV files
```
data/raw/patients.csv
data/raw/encounters.csv
data/raw/conditions.csv
data/raw/organizations.csv
```

### 4. Run the full pipeline
```bash
bash scripts/run_spark_pipeline.sh
```

### 5. Run Trino SQL analytics
```bash
# With Trino CLI
trino --server localhost:8080 --catalog iceberg --schema healthcare -f trino/queries/01_kpis.sql
```

### 6. Open Superset
```
http://localhost:8088
```

## Data Flow (Step by Step)

1. `spark/01_profile_dataset.py` — inspects raw CSVs, generates `docs/dataset_dictionary.md`
2. `spark/02_create_iceberg_tables.py` — creates Iceberg tables from CSVs
3. `spark/03_transform_healthcare_data.py` — cleans, joins, derives `healthcare_analytics`
4. `spark/04_export_mongodb.py` — writes aggregate summaries to MongoDB
5. Trino queries Iceberg tables via catalog configuration
6. Superset connects to Trino and renders dashboard

---

## Important Notes

- All records are **synthetic** — generated by Synthea, not real patients.
- Never run analytics on columns that do not exist in the real CSV files.
- Do not use Snowflake, Docker orchestration, or cloud services for this project.
- Superset is the UI only — not counted as a Big Data component.
