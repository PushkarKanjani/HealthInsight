# HealthInsight: Big Data Analytics Platform for Healthcare Data

> *HealthInsight is a local educational prototype for descriptive analytics over synthetic healthcare records.*

---

## 1. Project Purpose & Scope

HealthInsight is an on-premise, distributed Big Data analytics lakehouse platform engineered for descriptive analytics over large-scale synthetic longitudinal healthcare event records. 

The platform extracts, cleans, transforms, manages, queries, and visualizes **12,352 synthetic patients, 321,528 clinical encounters, and 114,544 diagnosed condition events**.

### Scope
- Distributed batch ETL and schema enforcement over high-volume healthcare CSV exports.
- ACID lakehouse storage and metadata pruning via Apache Iceberg table format.
- Interactive, sub-second distributed SQL analytics via Trino.
- Operational NoSQL pre-aggregated serving store via MongoDB.
- Clinical daylight BI dashboard via Apache Superset.

### Non-Goals
- **No Machine Learning / AI:** HealthInsight does not perform predictive disease diagnosis, clinical triage, or automated medical decision making.
- **No Real Protected Health Information (PHI):** The system does not store or process real human medical records.
- **Not Clinical Production Software:** It is an educational engineering prototype demonstrating big data architecture, storage engines, distributed SQL, and NoSQL serving patterns.

---

## 2. Dataset Source & Synthetic-Data Notice

- **Source:** Generated using the open-source **MITRE Synthea** patient simulation framework (Massachusetts synthetic healthcare population).
- **Format:** High-volume normalized CSV exports (`patients.csv`, `encounters.csv`, `conditions.csv`, `organizations.csv`).
- **Notice:** All patient identities, addresses, social security numbers, clinical diagnoses, and billing values are purely synthetic and generated by statistical simulation models.

## 3. Architecture & Component Roles

```
Synthea CSVs ──► Apache Spark 3.5 ──► Apache Iceberg 1.5 (Warehouse) ──► Trino 435 (Distributed SQL) ──► Apache Superset (UI)
                      │
                      └──► MongoDB 7.0 (NoSQL Operational Serving Layer)
```

| Component | Architecture Role | Execution Model | Storage Substrate |
|---|---|---|---|
| **Apache Spark 3.5** | Distributed Compute (Batch ETL) | Distributed DAG Engine | In-Memory JVM |
| **Apache Iceberg 1.5** | Open Lakehouse Table Format | Metadata-driven ACID Specification | Columnar Parquet + Avro/JSON Metadata |
| **Trino 435** | Interactive Distributed SQL Engine | Memory-Pipelined MPP Query Engine | Stateless (queries Iceberg directly) |
| **MongoDB 7.0** | NoSQL Operational Serving Store | Document / BSON Engine | WiredTiger Storage Engine |
| **Apache Superset 3.1** | BI & Dashboard Visualization | Web Application (Python/React) | Presentation Layer Only |

> [!IMPORTANT]
> **Apache Superset is NOT counted as one of the 4 Big Data components.** It is strictly the presentation and visualization UI. The four core Big Data components are Spark, Iceberg, Trino, and MongoDB.

## 5. Prerequisites & Environment Setup

### Prerequisites
- **Operating System:** Windows 10/11 64-bit with PowerShell 5.1+ / 7+
- **Docker Desktop:** Installed and running with WSL2 backend enabled
- **Python:** 3.10+ (tested on Python 3.11.9)
- **Java:** OpenJDK 17 LTS

### 1. Clone & Configure Environment
```bash
git clone https://github.com/PushkarKanjani/HealthInsight.git
cd HealthInsight
cp .env.example .env
```

Ensure `.env` contains:
```env
ICEBERG_WAREHOUSE=file:/warehouse
TRINO_HOST=localhost
TRINO_PORT=8080
MONGO_URI=mongodb://localhost:27017
SUPERSET_PORT=8088
```

### 2. Install Python Dependencies
```bash
pip install pyspark==3.5.3 pymongo trino
```

### 3. Start Infrastructure Services
```bash
docker compose up -d trino mongodb superset
```

Verify service health:
```bash
docker ps
```

## 6. Pipeline Execution

Run the complete, fail-fast automated pipeline:

### On Windows PowerShell:
```powershell
powershell -ExecutionPolicy Bypass -File scripts/run_pipeline.ps1
```

### On Linux / macOS / Bash:
```bash
bash scripts/run_pipeline.sh
```

### Pipeline Execution Order:
1. `spark/01_profile_dataset.py`: Profiles source CSVs and verifies schema integrity.
2. `spark/02_ingest_raw_to_iceberg.py`: Ingests raw CSVs into partitioned Iceberg lakehouse tables.
3. `spark/03_build_analytics_tables.py`: Constructs curated `encounter_analytics` and `condition_analytics` tables.
4. `spark/04_export_mongodb.py`: Aggregates metrics and populates 6 MongoDB collections.
5. `trino/queries/00_validation.sql`: Runs automated verification queries via Trino CLI.

## 7. Interactive Verification & Querying

### A. Trino Distributed SQL
Connect to Trino using any standard SQL client (e.g. DBeaver Community):
- **Host:** `localhost` | **Port:** `8080`
- **Catalog:** `iceberg` | **Schema:** `healthcare`
- **User:** `admin` (no password required)

Run sample queries from `trino/queries/`:
```sql
-- Check total encounter volume and average duration
SELECT encounter_class, COUNT(*) AS count, ROUND(AVG(duration_minutes), 1) AS avg_duration_mins
FROM iceberg.healthcare.encounter_analytics
GROUP BY encounter_class
ORDER BY count DESC;
```

### B. MongoDB Serving Layer
Connect via `mongosh`:

- **URL:** [http://localhost:8088](http://localhost:8088)
- **Credentials:** `admin` / `admin`
- **Dashboard:** Navigate to **Dashboards** -> **HealthInsight Healthcare Analytics**.

## 8. Data Invariants & Quality Guarantees

1. **Two-Table Separation (Zero Cost Inflation):**
   - Encounters and condition events are strictly partitioned into two analytical tables.
   - `iceberg.healthcare.encounter_analytics` (321,528 rows): Exactly 1 row per encounter (`COUNT(*) == COUNT(DISTINCT encounter_id)`). Financial sums remain 100% accurate.
   - `iceberg.healthcare.condition_analytics` (114,544 rows): 1 row per diagnosed condition event for epidemiology and prevalence metrics.
2. **Event-Time Relative Age Calculation:**
   - Patient age is calculated deterministically at encounter time (`DATEDIFF(encounter_start, patient_birthdate) / 365.25`), preventing anachronistic distortion from `CURRENT_DATE()`.
3. **Dual Storage Interoperability:**
   - Windows host Spark and Linux container Trino share the exact same Iceberg metadata via directory junction `C:\warehouse -> iceberg\warehouse`.

## 9. Troubleshooting

- **Trino cannot find tables:** Ensure tables are registered via `CALL iceberg.system.register_table(...)` after initial Spark creation.
- **Spark Iceberg Jar Error:** Ensure PySpark runs with `--packages org.apache.iceberg:iceberg-spark-runtime-3.5_2.12:1.5.2`.
- **Superset Trino Connection Refused:** Ensure the database URI is set to `trino://admin@trino:8080/iceberg/healthcare` (using container hostname `trino`, not `localhost`).

---

## 10. Known Limitations

- **Synthetic Simplicity:** Synthea generates simplified longitudinal trajectories; clinical nuances (such as ICD-10 coding hierarchies or multi-payer coordination of benefits) are abstracted.
- **Local Single-Node Lakehouse:** The prototype uses local disk and Docker containers rather than an enterprise distributed cluster (HDFS/S3/MinIO) and multi-node Trino coordinator/worker topologies.
